Generated by `node scripts/gen-owner-intake-w25.js` from `docs/PHOTO-SLOTS-W24.json`,
`content/garduri-modele.json` and the built pages. Not typed: a slot id typed by hand is
a file the intake will not find, because it matches on the filename being the slot id
exactly. `--check` fails if this file and the data have drifted apart.

**To take a drop in:** `node scripts/intake-owner-pics.js` reports what is waiting and
writes nothing. Add `--apply` plus `--who "<name>"` for a photograph or `--tool "<name>"`
for a generated image, and it installs, fills the ledger row and appends the provenance
row. It refuses a stem that is no slot id, a slot already filled, a file that is not an
image by its bytes, anything under the 450 floor, and a generated image where W25-R3 or
W25-R2 forbids one. **A missing file is listed, never an error.**

## The rule, once

- **The filename is the slot id**, plus an extension. `GARD-01.jpg`, `ACOP-02.png`.
- **Longest side 450 pixels or more.** Nothing is ever enlarged, so a smaller file is
  refused rather than stretched.
- **A real photograph goes in `/Users/ivan/RC-pics-real/`.** A generated one goes in `/Users/ivan/RC-pics-ai/`.
  They take different provenance rows, and a generated image is forbidden on some slots
  while a real one never is.
