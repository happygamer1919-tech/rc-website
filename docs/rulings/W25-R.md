## W25-R5 · Labelled swatches are installed, and flagged

> Swatch rule amended: Phomi colour swatches with the burned-in name are installed as is,
> each flagged in the review list. A family image still never fills a variant card.

**What it changes.** Answer set 2's swatch rule refused an image with a burned-in name
unless a crop removed it leaving both sides at 450 or more. On Phomi's 650x450 swatches no
such crop exists: the smallest crop that clears the label leaves 650x320 or 350x450, both
measured at W25-03c. That rule held 60 ceramic plates grey. It is now lifted **for these
images and by this route only**: they are installed as published, and the owner reviews
every one by hand.

**What it does not change.** The second clause stands untouched: **a family image never
fills a colour-variant card.** Gate 19 holds it as "two filled slots must not stand on the
same picture", which is unaffected.

**What the tooling does with it.** `scripts/process-packshot.js` keeps `--crop` and its
post-crop floor, because the arithmetic is still right whenever a crop IS the answer.
`--label` no longer refuses on its own: it records that a person saw a burned-in name, and
that flag is what `docs/PHOTO-REVIEW-W25.md` lists.

## W25-R6 · Discovery is free, download is not

> Discovery: web search and image search are allowed as discovery for any catalogue product.
> Download only from the manufacturer's page or its official distributor's page (example:
> Caparol Moldova, Caparol Shop). Never from fatade3d.md, imperlux.md, stock libraries, a
> page whose image carries another shop's watermark, or Russian domains. If the only
> findable image of a product lives on fatade3d.md, the slot stays placeholder and is listed
> with that reason.

**This separates the two halves that W25-02 ran together and answer set 1 split by method.**
Finding a product's page may now use any search, including image search. Deciding whether a
URL may be FETCHED is unchanged and stays in `scripts/fetch-packshot.js`, which is the only
thing in the repo that reaches the network for an image.

**"Its official distributor's page" is widened by example**, not by principle: W25-R1 already
allowed the official national distributor domain named on the manufacturer's site, and the
owner names Caparol Moldova and Caparol Shop as instances. A shop that merely sells the
brand is not a distributor page.

**A findable-only-on-fatade3d image is a reported placeholder**, never a quiet omission.

## W25-R8 · Prices: the current public one, and nothing else

> Prices: copy the current public price only (de la X lei). Never copy strike-through old
> prices, percent badges, countdowns or stock-limited claims (R-X). Public list prices are
> not supplier purchase prices; nothing from invoices enters the repo.

**R-X already forbids the second half** and `scripts/check-scarcity.js` enforces it: no

page shows today, and not the number it is discounted from.

**"Nothing from invoices enters the repo"** is a boundary about the client's own purchase
prices and it is absolute.

## W25-R11 · Gate 9 waits before it measures, and re-reads only as a fallback

> Q-W25-15 approved with a condition. Root fix first: verify-live waits for stylesheet
> applied and promo bar present before measuring. Re-read is the fallback only: max 2
> re-reads, unverified rows only, never failed rows. Every re-read row prints RETRIED with
> both readings and the run summary counts them. R-AB holds: exit code stays the result.

**The condition is the whole ruling.** Q-W25-15 offered a re-read as the recommended option
and the owner refused it as the primary: a re-read hides a slow page rather than fixing it,
and a gate that quietly passes on the second try is a gate that has learned to look away.

**"Stylesheet applied and promo bar present" is a real readiness signal and not a sleep.**
Every one of the ten marker sets in `MARKERS` expects `promoBar: 1`, so the promo bar is on
every page this gate reads, and its absence is what the false red actually reported. A
stylesheet that has applied is detectable without guessing at a duration: the site's design
tokens are custom properties declared in `src/styles.css`, so `--brand` resolving to a
non-empty value on `:root` is the stylesheet, by definition, having applied.

**The fallback is bounded in three directions at once**: at most two re-reads, only for a
row that came back UNVERIFIED, and never for a row that FAILED. A failure is a measurement
about the site; an unverified row can be a measurement about the instrument, and only the
second kind may be read again.

**Every re-read is printed, both readings, and counted in the summary.** A re-read nobody
can see is indistinguishable from a gate that passes on the second try, which is the thing
the owner refused.

**R-AB holds and is restated**: the exit code is the result. A run whose retries all
succeeded exits 0; a run with a row still unverified after two re-reads exits 1.

## W25-R13 · Duplicate catalogue records

> Duplicate records: if name, unit and price are identical, drop one record and keep the URL
> of the older id. If anything differs, block with a question quoting both rows.

**Identical on all three means one product listed twice**, and the site should say so once.
"Keep the URL of the older id" is what stops a link that already exists from breaking:
whichever record was captured first keeps its slug.

**Anything else is a product decision and stops the card.** Two records of one tile in
different sheet sizes, at different prices, are two things the shop sells, and merging them
is the owner's call, not this terminal's. The question quotes **both rows**, so the decision
is made against the data rather than against a description of it.
