## W25-R5 · Labelled swatches are installed, and flagged

> Swatch rule amended: Phomi colour swatches with the burned-in name are installed as is,

## W25-R11 · Gate 9 waits before it measures, and re-reads only as a fallback

> Q-W25-15 approved with a condition. Root fix first: verify-live waits for stylesheet
> applied and promo bar present before measuring. Re-read is the fallback only: max 2
> re-reads, unverified rows only, never failed rows. Every re-read row prints RETRIED with
> both readings and the run summary counts them. R-AB holds: exit code stays the result.

**The condition is the whole ruling.** Q-W25-15 offered a re-read as the recommended option
and the owner refused it as the primary: a re-read hides a slow page rather than fixing it,
and a gate that quietly passes on the second try is a gate that has learned to look away.

**"Stylesheet applied and promo bar present" is a real readiness signal and not a sleep.**
Every one of the ten marker sets in `MARKERS` expects `promoBar: 1`, so the promo bar is on
every page this gate reads, and its absence is what the false red actually reported. A
stylesheet that has applied is detectable without guessing at a duration: the site's design
tokens are custom properties declared in `src/styles.css`, so `--brand` resolving to a
non-empty value on `:root` is the stylesheet, by definition, having applied.

**The fallback is bounded in three directions at once**: at most two re-reads, only for a
row that came back UNVERIFIED, and never for a row that FAILED. A failure is a measurement
about the site; an unverified row can be a measurement about the instrument, and only the
second kind may be read again.

**Every re-read is printed, both readings, and counted in the summary.** A re-read nobody
can see is indistinguishable from a gate that passes on the second try, which is the thing
the owner refused.

**R-AB holds and is restated**: the exit code is the result. A run whose retries all
succeeded exits 0; a run with a row still unverified after two re-reads exits 1.

## W25-R17 · Q-W25-13 amended, one picture may fill several records

> the review file. A picture never fills a different product.

**The rule is not dropped, it is narrowed.** W25-R3's "one picture never stands as two

W25-R5 and W25-R7 already have: gate 24 generates a `reuse` flag from the ledger field, so a

## W25-R20 · Where a product picture comes from, in order

> Sourcing rule, standing: a product picture comes first from the site its data and price came
> from. If none there at floor 450, use Google image search, pick the best match at 450 or more
> from any site except Russian domains, log the source URL, flag google_pick in the review file.

**This is a standing rule, not a card, and it reorders every earlier sourcing instruction
without contradicting one.** W25-R1 preferred the manufacturer's own site, W25-R6 made

**The order is: the site the data came from, then anywhere.** "The site its data and price came

1. **450 or more.** The floor does not move; W25-R12 said final and this does not reopen it.

3. **The source URL is logged and the row is flagged `google_pick` in the review file.** The

marketplace's own product listing, never a search result thumbnail, never an image carrying

## W25-R24 · A hub tile's link answers 200, and a gate says so

> Hub tile links: every hub tile on /servicii/acoperisuri/ and /servicii/garduri/ (RO and RU)
> has an href that answers 200. Add this to gate 20 or as a new gate.

**This exists because one of them did not.** The Garduri hub's "tip jaluzele" tile pointed at
nothing that answers, and `scripts/check-links.js` did not catch it, which is the fact that
makes this a gate rather than a fix: a link checker that passed a dead tile is a link checker
that will pass the next one.

**It is a new gate rather than an addition to gate 20.** Gate 20 measures painted geometry and
knows nothing about hrefs; a link assertion inside it would be a second thing in a box labelled
one thing. The new gate reads the built pages, so it needs no network: a hub tile's href is
either a page this build emits or it is not.
