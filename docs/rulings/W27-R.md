## W27-R-01 · Self-merge for wave 27

> Ruling W27-R-01 (record first, see rulings block): for wave 27 only, EXECUTOR merges its own
> PRs on green quality check. This overrides R-V for this wave. R-Z stands: never the web editor
> on conflict, rebase on main and re-run.

**Scope: wave 27 only.** R-V's wave 19 amendment ("from wave 19 onward no card self-merges") is
overridden for the cards of this wave and for nothing else. Wave 28's cards, if any are dispatched
under that name, are not covered unless the owner says so again. The W28-numbered DESIGN cards
this dispatch carries (W28-01 to W28-08 and W28-T) are wave 27 cards by the dispatch's own
words ("STEP 3: DESIGN CARDS" of the wave 27 run) and are covered.

**"On green quality check" is the whole condition.** A merge happens only after the `quality`
job has reported success on the PR's head sha, and never before. The merge protocol the owner
wrote is followed step by step, with two deviations forced by what the preflight found, each
recorded here and in the report:

1. **`main` carried no branch protection at all** at preflight (the API answered
   `Branch not protected`, 404; rulesets: `[]`). There was therefore no
   `required_pull_request_reviews` to remove and no required check to preserve. Nothing was
   deleted. The consequence is that GitHub's own auto-merge has nothing to wait for, so the
   "green before merge" condition is enforced by the protocol's own order instead:
   `gh pr checks --watch` must exit 0 first, then the merge is called. Auto-merge was still
   enabled on the repository as instructed (`gh repo edit --enable-auto-merge`, exit 0).
2. **The merge is a merge commit, not a squash.** `docs/CLAUDE.md` section 10: "Every change on
   `main` arrives through a `--no-ff` merge commit. `git log --no-merges --first-parent` on
   `main` should return only the initial scaffold commit." Every merge on this repo to date is
   one, #1 to #135. A squash would put the first non-merge commit on main's first-parent line
   since the scaffold. "Ground truth is the repo" resolves the conflict in favour of the repo's
   rule; one card is still one commit, on its branch.

**R-Z stands unchanged.** A conflict is resolved locally by rebasing on `main` and re-running
the gates. The web editor is never opened.

**What the harness may still refuse.** The Claude Code permission layer has refused
`gh pr merge` as "Merge Without Review" before on this repo (R-V's wave 19 amendment records
#44). The dispatch names the fallback: if the first merge is refused for a permission reason,
every remaining card lands as a commit on one branch `w27-final` behind one PR for the owner,
and the report's first line reads `FALLBACK MODE`.
